# Judo Technique Visualizer

A 3D app that shows judo techniques step by step on two judoka: Tori (white gi), who does the technique,
and Uki (blue gi), who receives it. Pick a technique, play it in slow motion or frame by frame, and watch it
from any side or through the eyes of either judoka. Every phase (kumikata, kuzushi, tsukuri, kake, ...)
has a short Dutch description of what each hand and foot does.

![O-soto-gari at kake, seen from the side](docs/images/o_soto_gari.png)

The target audience is a beginner preparing a belt exam on their own: the animations aim for the
textbook (Kodokan / VJF) form, right-handed, as practised in uchikomi and nage-komi.

## Status

- **Catalogue:** all 101 techniques: the 46 of the VJF *Leerlijn voor Kyu-graden* (2015), the Flemish
  judo federation's kyu syllabus, plus 55 other Kodokan techniques. They are grouped by kyu grade and belt
  colour. Shime- and kansetsu-waza (strangles and arm locks) are hidden unless "U18" is switched on.
- **Animated:** ippon-seoi-nage, koshi-guruma, o-soto-gari, o-uchi-gari and kuzure-kesa-gatame. The other
  techniques show their information and "Nog geen animatie" (no animation yet).
- **Next milestone:** all eight yellow-belt (5th kyu) techniques good enough for a white belt to learn
  from. Still to animate for that: uki-goshi, kami-shiho-gatame, yoko-shiho-gatame and tate-shiho-gatame.
  The animated techniques still have known issues (limbs overlapping, a grip that lets go); they are listed
  under *Status* in [CLAUDE.md](CLAUDE.md).

Help is welcome, especially from judoka: see [CONTRIBUTING.md](CONTRIBUTING.md).

## Using the app

| Control | Action |
| ------- | ------ |
| Technique list (left) | Pick a technique; filter on a grade; "U18-technieken tonen" adds shime- and kansetsu-waza |
| Space | Play / pause |
| `,` / `.` | One frame back / forward |
| Timeline, `\|<` `>\|` | Scrub; jump to the previous / next phase |
| Speed, Reverse, Loop | Slow motion (0.1x to 2x), play backwards, repeat |
| 1 / 2 / 3, C | Camera: orbit / through Tori's eyes / through Uki's eyes; C = next |
| Arrow keys, mouse drag, wheel | Orbit camera: circle around, move closer or further |
| F2 | Pose feedback: click a body part and type what is wrong (development builds) |
| F3 | Pose editor: correct a body part at a keyframe (development builds) |

## Getting started

Developed and tested on Windows. You need:

- [Godot 4.7.2, .NET edition](https://godotengine.org/download/archive/4.7.2-stable/), by default in
  `C:\tools\godot`. Elsewhere: set `GODOT` to the path of `Godot_v4.7.2-stable_mono_win64_console.exe`.
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0)
- [Git LFS](https://git-lfs.com/): models and images are stored with it. Run `git lfs install` once
  before cloning.
- Only to change animations: [Blender 5.2.2](https://www.blender.org/download/releases/5-2/), in
  `C:\tools\blender`.

```powershell
git clone https://github.com/pvoosten/judovis.git
cd judovis
.\run.ps1                                   # build and start the app (-Console shows Godot's log)
.\build.ps1                                 # build, unit tests, asset import, headless smoke test
.\build.ps1 -Configuration Release -Export  # also a Windows build in build\windows\JudoVisualizer.exe
```

## How it works

Each technique is a YAML file in [`data/techniques/`](data/techniques/). It holds the names, the kyu grade
and belt, and keyframes: the time, the phase, the Dutch description and the pose of both judoka. The Godot
app (C#) loads these files and interpolates between the keyframes.

The keyframes are not written by hand. A Python script per technique in
[`tools/blender/techniques/`](tools/blender/techniques/) poses the two judoka in Blender. Shared tools then
keep planted feet still, shift the weight, keep the grips on the gi and push overlapping bodies apart. The
script checks the result (contact, foot sliding, balance) and exports the YAML. Corrections made in the app
with the pose editor (F3) are applied on top of the script's poses, so a Blender run keeps them.

| Path | Contents |
| ---- | -------- |
| `src/` | The Godot app (C#): data model, playback, cameras, user interface |
| `data/techniques/` | One YAML file per technique (generated by the Blender scripts, except the catalogue-only entries) |
| `tools/blender/` | Blender scripts that build the judoka and author the techniques; see its [README](tools/blender/README.md) |
| `feedback/`, `edits/` | Pose comments (F2) and pose corrections (F3) made in the app |
| `tests/` | Unit tests |
| `CLAUDE.md` | Project conventions, the YAML schema, the current status and the *definition of done* for a technique |

The project is developed with [Claude Code](https://claude.com/claude-code); `CLAUDE.md` holds the
instructions it works from, and doubles as the developer documentation.
